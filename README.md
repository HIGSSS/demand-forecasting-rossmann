# Demand Forecasting: прогноз продаж магазинов на 14 дней

Прогноз ежедневных продаж сети магазинов на горизонт 14 дней (датасет Rossmann Store Sales). Цель проекта: построить модель, которая заметно лучше простых бизнес-правил, и проверить её так, как это делают на практике, то есть по времени, без утечки данных из будущего.

## Результат в двух словах
LightGBM ошибается примерно вдвое меньше лучшего простого baseline: WAPE **8,6%** против **16,4%**, MAE **597** против **1145** на hold-out из последних 6 недель. История продаж (лаги) даёт основной вклад: без неё ошибка выше на треть.

## Данные
[Rossmann Store Sales](https://www.kaggle.com/c/rossmann-store-sales/data) (Kaggle): ежедневные продажи магазинов сети, промо-акции, праздники, тип магазина, расстояние до конкурентов. Файлы `train.csv` и `store.csv` кладутся в папку `data/`.

Для обучения и оценки использованы только дни, когда магазин был открыт и продажи были положительными: после подготовки признаков получилось 789 620 строк для обучения и 40 282 строки для hold-out.

## Постановка и валидация
- **Горизонт:** 14 дней. Все лаги и скользящие признаки сдвинуты минимум на 14 дней, поэтому на момент прогноза используется только та информация, которая реально была бы доступна. Это защита от утечки данных (data leakage).
- **Hold-out:** последние 6 недель данных. Всё, что раньше, используется для обучения.
- **Кросс-валидация по времени:** `TimeSeriesSplit` с 4 фолдами на обучающей части. Случайное разбиение для временных рядов не подходит, так как модель «видела бы» будущее.
- **Метрики:** MAE, RMSE и WAPE = сумма абсолютных ошибок / сумма фактических продаж. WAPE устойчив к магазинам с разным масштабом продаж и легко интерпретируется как «доля ошибки от общих продаж».

## Признаки
- календарь: день недели, месяц, день, неделя года, год;
- промо, школьные каникулы, государственные праздники;
- характеристики магазина: тип, ассортимент, расстояние до конкурента;
- лаги продаж: 14, 21, 28 и 364 дня назад;
- скользящие среднее (окна 7 и 28 дней) и стандартное отклонение (28 дней), посчитанные по данным со сдвигом на 14 дней.

## Модели
1. **Baseline 1:** продажи 28 дней назад (сезонный наивный прогноз).
2. **Baseline 2:** среднее по магазину и дню недели на обучающей части.
3. **LightGBM без лагов:** только календарь, промо и характеристики магазина (абляция: показывает вклад истории продаж).
4. **LightGBM полный:** все признаки, функция потерь `regression_l1`.

## Результаты (hold-out, последние 6 недель)

| Модель | MAE | RMSE | WAPE |
|:--|--:|--:|--:|
| Baseline 1: значение 28 дней назад | 1145,1 | 1909,4 | 16,4% |
| Baseline 2: среднее по магазину и дню недели | 1252,9 | 1661,8 | 17,9% |
| LightGBM без лагов (календарь + промо) | 910,7 | 1371,8 | 13,1% |
| **LightGBM полный (лаги + календарь + промо)** | **597,0** | **888,8** | **8,6%** |

Кросс-валидация по времени (4 фолда), WAPE полной модели: 11,9%, 14,2%, 10,5%, 10,8%, в среднем **11,9%**.

## Выводы
- **Качество относительно baseline.** WAPE полной модели почти вдвое ниже, чем у лучшего baseline (8,6% против 16,4%), MAE ниже с 1145 до 597.
- **Вклад истории продаж.** Добавление лагов и скользящих статистик снижает WAPE с 13,1% до 8,6% (примерно на треть). Одни только календарь и промо дают заметно меньше.
- **Устойчивость.** Ошибка на кросс-валидации выше (в среднем 11,9%), чем на hold-out (8,6%), и сильно зависит от периода (фолд 2 хуже всех, 14,2%). Поэтому оценку по одному периоду нельзя считать окончательной: реальное качество на новых периодах может быть ближе к 11–12%.
- **Детальный разбор ошибок** по дням недели, промо, праздникам и магазинам (в том числе 10 худших магазинов) сохраняется в `results.md` и `error_analysis.png`.

## Структура репозитория
```
forecast.py        # признаки, baseline-ы, обучение, валидация, анализ ошибок
make_synthetic.py  # синтетические данные для проверки кода (не для оценки качества)
requirements.txt
results.md         # итоговые таблицы, включая анализ ошибок
forecast_vs_actual.png, feature_importance.png, error_analysis.png
```

## Как запустить
```bash
pip install -r requirements.txt
# положите train.csv и store.csv в data/
python forecast.py            # обучение и оценка
python forecast.py --tune     # то же + подбор гиперпараметров по TimeSeriesSplit (дольше)
```
Результаты воспроизводимы (`random_state=42`).

## Ограничения и возможные улучшения
- Нет внешних признаков (погода, события); прогноз по каждому магазину строится независимо, без иерархической согласованности.
- Не сравнивал со статистическими моделями (ETS, Prophet) и нейросетевыми подходами.
- Описанные результаты получены без подбора гиперпараметров; запуск с `--tune` может улучшить метрики.
